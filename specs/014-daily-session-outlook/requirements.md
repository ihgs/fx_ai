# 014 デイリーセッション見通し (daily-session-outlook)

## Overview

毎日JST 6:30に、直近営業日までのレートデータ（既存`rate_candles`をセッション時間帯ごとに集計したもの）を入力として、当日の東京・ロンドン・NY市場それぞれの見通し（方向性・根拠）をAIに生成させる。分析ページの先頭に直近の見通しをまとめて表示し、その下に従来の（毎時の）分析結果を直近1週間分表示する。新規の外部データ連携（経済指標カレンダー等）は今回は行わない。

セッション時間帯（JST、年間固定・夏時間非対応。既存の`weeklyHistory.ts`と同様の方針）:
- 東京市場: 9:00〜18:00
- ロンドン市場: 17:00〜翌2:00
- NY市場: 22:00〜翌7:00

## User Stories

### Story 1: 毎朝自動でセッション別の見通しが生成される

As a ユーザー,
I want 毎日JST6:30に東京・ロンドン・NY市場それぞれの当日の見通しが自動生成されてほしい,
So that 朝の時点で1日のトレードプランを立てられる。

- 1.1 WHEN JST 6:30になったとき（平日・かつその日の分がまだ生成されていない場合）THE SYSTEM SHALL 東京・ロンドン・NY市場それぞれの当日の見通し（方向: 上昇/下落/横ばい、根拠）を生成し保存する。
- 1.2 THE SYSTEM SHALL 各セッションの見通し生成にあたり、直近営業日（前営業日、土日を除く）のセッション別（上記時間帯）の高値・安値・始値・終値、および全体のトレンド・値幅を入力情報として使用する。
- 1.3 IF 当日が土曜日または日曜日のとき THEN THE SYSTEM SHALL 見通し生成をスキップする（既存の週末休場判定に準ずる）。
- 1.4 IF 直近営業日のレートデータが1件も存在しない場合 THEN THE SYSTEM SHALL 見通し生成をスキップし、その旨をログに記録する。
- 1.5 IF 同じ日の見通しが既に生成済みの場合（サーバー再起動等による重複実行防止）THEN THE SYSTEM SHALL 再生成しない。
- 1.6 WHEN AIへの問い合わせが1セッション分失敗したとき THEN THE SYSTEM SHALL 他のセッションの生成には影響を与えず、失敗したセッションのみスキップしログに記録する。

### Story 2: 生成された見通しを確認する

As a ユーザー,
I want 分析ページの先頭で直近の東京/ロンドン/NY見通しをまとめて確認し、その下で従来の（毎時の）分析結果を直近1週間分確認したい,
So that 一目で今日の見通しを把握しつつ、必要であれば過去の分析も遡って確認できる。

- 2.1 WHEN 分析ページを開いたとき THE SYSTEM SHALL 直近（最新）の東京・ロンドン・NY見通しをページ先頭にまとめて表示する。
- 2.2 THE SYSTEM SHALL ページ先頭の見通し表示の下に、従来の（毎時の）分析結果一覧を表示する。
- 2.3 THE SYSTEM SHALL 従来の分析結果一覧の表示件数を直近最大1週間分とする。
- 2.4 THE SYSTEM SHALL セッション別見通しについても、既存の正誤判定・正答率集計の仕組みをそのまま適用する（各セッション終了時点の実レートと比較して正解/不正解を判定する）。
- 2.5 IF まだ見通しが1件も生成されていない場合 THEN THE SYSTEM SHALL 先頭のセッション別見通し表示を空状態にする（従来の分析結果一覧は通常どおり表示する）。

## Out of Scope

- 経済指標カレンダー・ドルインデックス(DXY)・米国株指数等、既存`rate_candles`以外の新規外部データ連携
- 分析ページとは別の、専用の新しい画面・ルート（あくまで既存の分析ページ内でのレイアウト変更に留める）
- 過去日分の見通しの遡及生成（バックフィル）
- 6:30以外の時刻でのオンデマンド生成（既存の「分析実行」ボタンは今回の対象外のまま）
- 夏時間(DST)によるセッション時間帯の切り替え（年間固定のJST時間帯を使う）
