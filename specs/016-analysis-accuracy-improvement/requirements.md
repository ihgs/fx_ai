# AI分析の精度向上（追加指標とプロンプト改訂） — Requirements

## Overview
`analysis_log/fx_export_2026-09-13_2026-09-19.json`（直近1週間の分析結果）を集計したところ、method=v2の正答率は55.4%（flat外れを除く現行集計）で、特に以下の課題が判明した。

- flat予測の過少使用: 実際にflatだったのは32%だが、AIがflatと予測したのは12%のみ。
- down予測の信頼性が低い: down予測30件のうち的中はわずか9件（30%）で、実際はupだったケースの方が多い（11件）。
- rationale本文を確認すると、デッドクロス/ゴールデンクロスの発生や直近高値・安値の更新のみを根拠に方向を断定し、その直後に反転しているケースが繰り返し見られる（遅行指標への依存、オーバーエクステンションの見落とし）。
- 入力窓が直近120分のみのため、週全体の上昇基調（153.4円→156円台）のような長期の文脈を踏まえられていない。

本specは、既存のspec 009（テクニカル指標導入）を拡張し、(a) 乖離幅（オーバーエクステンション）と長期トレンドの追加指標を算出してプロンプトに含める、(b) 単一指標への依存を避けflatを選びやすくするようプロンプトの判断基準を改訂する、の2点でAI分析（1時間先予測・デイリーセッション見通し）の精度改善を図る。

## User Stories

### 1. 乖離幅（オーバーエクステンション）指標の追加
As a ユーザー, I want 現在値が移動平均線からどれだけ乖離しているかをAIが判断材料にしてほしい, So that 値動きが伸びきった直後に安易に継続と判断するのを避けられる。

- 1.1 WHEN AI分析を実行する THE SYSTEM SHALL 現在値と短期移動平均線の差をボラティリティ（標準偏差）に対する比率として算出する。
- 1.2 WHEN プロンプトを構築する THE SYSTEM SHALL 算出した乖離幅をAIへの入力に含める。
- 1.3 IF ボラティリティが0、または短期移動平均が算出不可 THEN THE SYSTEM SHALL 乖離幅を算出不可として扱い、分析自体は継続する。

### 2. 長期トレンド指標の追加
As a ユーザー, I want 直近120分より長い期間のトレンドもAIが判断材料にしてほしい, So that 大きな上昇/下降トレンドの中の一時的な押し目・戻りを、トレンド転換と誤認しにくくなる。

- 2.1 WHEN AI分析（1時間先予測）を実行する THE SYSTEM SHALL 直近24時間の変化率（期間の始値と終値の比較）を算出する。
- 2.2 WHEN プロンプトを構築する THE SYSTEM SHALL 直近120分の値動きに加えて、直近24時間の変化率をAIへの入力に含める。
- 2.3 IF 24時間分のレート履歴が存在しない（サービス運用開始直後など） THEN THE SYSTEM SHALL 長期トレンド指標を算出不可として扱い、分析自体は継続する。

### 3. プロンプトの判断基準の改訂
As a ユーザー, I want AIが単一の指標だけで方向を断定せず、根拠が弱い場合はflatを選ぶようにしてほしい, So that 実際の横ばい相場をup/downと誤判定するケースが減る。

- 3.1 WHEN プロンプトを構築する THE SYSTEM SHALL 移動平均クロスの発生のみでなく、複数の指標（クロスの方向・変化率の符号・乖離幅・長期トレンド）が同じ方向を示す場合に限りup/downと判定するよう指示する文言を含める。
- 3.2 WHEN プロンプトを構築する THE SYSTEM SHALL 直近で高値・安値を更新した直後の値動きを、反転リスクを考慮せず継続シグナルとして採用しないよう注意喚起する文言を含める。
- 3.3 WHEN プロンプトを構築する THE SYSTEM SHALL 明確な根拠がそろわない場合はflatを選択するよう指示する文言を含める。
- 3.4 この判断基準の改訂は `lib/analyzeRate.ts`（1時間先予測）と `lib/dailyOutlook.ts`（デイリーセッション見通し）の両方のプロンプトに適用する。長期トレンド指標（Story 2）は1時間先予測（`analyzeRate.ts`）にのみ適用し、デイリーセッション見通し（`dailyOutlook.ts`）は既存どおり前営業日の各セッション統計を長期文脈として用いる。

### 4. 新旧分析手法の区別（spec 009のパターンを踏襲）
As a ユーザー, I want 本spec適用後の分析結果を、既存の"v2"の正答率統計と区別したい, So that 手法変更の前後で精度比較ができ、既存の統計が汚染されない。

- 4.1 WHEN 本spec適用後にAI分析（1時間先予測）を実行する THE SYSTEM SHALL method識別子を"v3"として保存する。

## Out of Scope
- `judgeAnalysis.ts` の `FLAT_THRESHOLD_JPY`（横ばい判定閾値）の変更
- `dailyOutlook.ts` 側のmethod識別子（daily-tokyo等）のバージョニング（既存のまま。サンプル数が少なく、今回のプロンプト改訂も軽微な追記のため）
- 算出した指標のUI（分析結果画面）への表示
- 指標のDBへの永続化（都度計算する、既存踏襲）
- 新旧手法（v2 / v3）の精度比較ダッシュボードやバックテスト
- RSI/MACDなど、既存のレート履歴だけでは算出できない高度なテクニカル指標ライブラリの導入
