# AI分析の高度化（テクニカル指標） — Requirements

## Overview
spec 004 のAI分析は、直近120分の1分足終値（bid）の羅列をそのままプロンプトに渡し、AIに傾向を読み取らせているだけで、数値からの傾向抽出をAI任せにしている。移動平均・変化率・ボラティリティなどのテクニカル指標を事前に計算してプロンプトに含めることで、分析の根拠を安定させ、判定の質を上げる。

## User Stories

### 1. テクニカル指標に基づく分析
As a ユーザー, I want AI分析がテクニカル指標（移動平均・変化率・ボラティリティ等）に基づいて判断してほしい, So that 生の数値の羅列だけに頼るより安定した根拠のある見通しを得られる。

- 1.1 WHEN AI分析を実行する THE SYSTEM SHALL 直近のレート履歴から短期・長期の移動平均、直近の変化率（騰落率）、ボラティリティ（標準偏差）、期間内の高値・安値を算出する。
- 1.2 WHEN プロンプトを構築する THE SYSTEM SHALL 生の終値の時系列に加えて、算出したテクニカル指標のサマリーをAIへの入力に含める。
- 1.3 WHEN AI分析結果を保存する THE SYSTEM SHALL 既存のDBスキーマ（direction, rationale, target_at 等）を変更せずに保存する。
- 1.4 IF レート履歴の件数が長期移動平均などの計算に必要な最小件数に満たない THEN THE SYSTEM SHALL 計算可能な指標のみ算出し、分析自体は継続する（履歴が0件の場合にエラーとする既存動作は維持）。

### 2. 分析手法の区別
As a ユーザー, I want 指標ベースに変わった新しい分析結果を、これまでの単純な分析結果と区別して正答率を追跡したい, So that 手法変更の前後で精度比較ができ、既存の正答率統計（spec 005）が汚染されない。

- 2.1 WHEN 本spec適用後にAI分析を実行する THE SYSTEM SHALL 既存の `method="v1"` とは異なる識別子で分析結果を保存する。

## Out of Scope
- 算出したテクニカル指標そのものをUI（分析結果画面）に表示すること
- 複数の分析手法をユーザーが選択するUI（method切り替えUIは spec 005 の範囲外のまま）
- テクニカル指標のDBへの永続化（都度計算する）
- 新旧手法の精度を比較するダッシュボードやバックテスト
